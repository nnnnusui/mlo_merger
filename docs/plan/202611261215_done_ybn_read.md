# YBN Read Plan

## Goal

Read YBNs with `--read` as YMAPs are read, into JSON documents that name collision flags, so
tools and people see what each child collides as and with without decoding bits.

## Findings

- `--read` reads YMAPs only, into `YmapReadDocument`s under `asset/map/read-cache`.
- A YBN child's flags are the `EBoundCompositeFlags` pair of CodeWalker
  (`CodeWalker.Core/GameFiles/Resources/Bounds.cs`): the first names what the collision is
  (`MAP_WEAPON`, `MAP_DYNAMIC`, ...), the second what it collides with (`PED`,
  `PROJECTILE`, ...). Bit 0 is `UNKNOWN`.
- Materials have their own names (surface types, flags), which CodeWalker also lists.

## Phases

### 1. Flag Names

- [x] Name the 32 bits of `EBoundCompositeFlags`, and write a child's flags as
  `{ "value": 62, "names": ["MAP_WEAPON", "MAP_DYNAMIC", ...] }`, one object per member of the
  pair, labelled `type` and `include`. Unnamed bits stay in `value`.
- [x] Tests: set bits are named; a value round-trips through `value`.

### 2. Reading YBNs

- [x] Read `.ybn` files with `--read` and `--read --all`, from resources, history and vanilla,
  into `YbnReadDocument`s at the same paths with `.ybn.json`: the bound tree with each child's
  kind, flags, transform and geometry, its vertices in a table the polygons index.
- [x] Add the document to the TypeScript types.

### 3. Material Names

- [x] Name material flags as child flags are named, after CodeWalker's
  `EBoundMaterialFlags`.
- [ ] Name surface types: CodeWalker reads them from the game's `materials.dat`, which the
  vanilla archive does not collect (see `docs/TODO.md`).

### 4. Docs

- [x] Describe YBN documents in `docs/usage.md` (`--read`) and `docs/reference.md`.

## Decisions

- Geometries keep their vertex table, polygons indexing it, rather than each polygon resolved
  to positions: resolved positions made documents about 8 times the size of their YBN (21 GB
  for the latest stage's 13926 vanilla YBNs), the table about 3.6 times.
- Material flags are named without CodeWalker's `FLAG_` prefix.
